# 技术架构与自研 Agent 价值

本项目在现有 Node.js CommonJS 工作台上增量开发，不依赖复杂 Agent 框架。实际入口为 `src/server.cjs`，多阶段编排为 `src/orchestrator.cjs`，运行提示词为 `src/prompts.cjs`。模型端点、模型名与凭证读取沿用 `src/model.cjs` 和现有配置，不在文档重写或猜测。

## 实际执行闭环

1. 解析：结合原始任务、当前稿件和用户修改，输出人群、场景、购买阶段、痛点、目标、平台与修改范围；关键信息不足才追问。
2. 规划：独立模型调用输出客户洞察、内容切入、卖点优先级、结构、CTA 理由、最多五条事实/限制/指南查询与图片需求。
3. 研究：工具实际执行模型查询，在目标型号资料中按主题和关键词排序。场景指南仅用于策略，不作为产品事实。缺口检查可提出新的补查查询。
4. 写作：将确认的策略、证据、限制和图片候选传入创作角色。图片由索引选择，事实使用证据编号关联。
5. 审核：独立模型从完整可发布文本重新提取产品陈述，逐项核对支持关系、条件、型号与承诺；程序再检查引用归属、数字单位、图片与合规。
6. 修订：最多两次针对性修订并重新审核，必要时补查。冲突立即停止；有限修订后仍不通过则阻止交付。
7. 会话与导出：仅通过稿件可复制和导出。局部修改由段落补丁合并，未授权段落由代码保留；切平台、人群、产品或核心卖点重新规划。

这些阶段使用同一个已配置的 DeepSeek 模型，以不同职责提示词和结构化输入输出分工。查询、策略和审核结果会改变实际控制流，不只是进度条名称。页面展示的是结构化决策摘要，不展示模型内部思维链。

## 状态与边界

会话存于服务进程内存，维护当前任务、策略、证据、稿件和有限版本历史；服务重启后不保留。图片核验针对索引、型号和文件格式，不代表已做视觉识别或授权审核。规则与 LLM 辅助审核均可能漏检，不能称为绝对可靠事实证明。

## 数据源与降级

最新赛事变更以用户提供的主办方通知为依据：ima 不再强制。正常模式读取授权本地库，可结合针对性的官网产品取证；ima 适配保留但不作为必须依赖，不继续排查赛事端故障。官网能力的实际可用性以本轮测试记录为准，不能仅凭配置存在宣称已通过。

事实记录应保留型号、配置条件、原始片段、来源类型、标题、路径或 URL、获取时间和源文日期；图片保留型号与来源。官网访问失败应保留失败状态并回退本地，禁止把本地缓存说成实时官网结果。相同条件冲突阻止交付；不同配置或版本不能直接合并为单一事实。

## 公开交付边界

只发布源码、配置模板、文档与清晰标记的少量 Demo 数据。完整参考资料、凭证、原始运行输出和授权不明的图片不进入公开仓库。Demo 必须标明模拟资料与示意图，不能用于证明华为真实规格。
