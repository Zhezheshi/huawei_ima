# 实际运行提示词设计

唯一运行定义位于 `src/prompts.cjs`。`prompt(stage)` 将公共八模块与当前阶段指令拼接，编排器在每次角色调用中使用；本文件解释作用，不替代实际源文件。提交时可附该源文件供评审核查。

| 手册模块 | 程序中的实际约束 | 作用 |
|---|---|---|
| 角色与任务 | 有证据的华为 PC 原创图文、当前阶段职责、JSON 输出 | 明确交付目标与角色边界 |
| 场景理解 | 人群、混合场景、购买阶段、痛点、目标；必要时追问 | 决定策略而非套固定模板 |
| 平台规则 | 输入 platformRules，平台切换覆盖旧稿 | 改变篇幅、结构、语气、图数与 CTA |
| 知识库约束 | 当前数据源的同型号证据；指南不能证明产品事实 | 限制模型知识与来源混用 |
| 图片规则 | 只选工具返回的同型号 ID、图注、位置；索引核验边界 | 防止虚构图片与错配型号 |
| 生成要求 | 标题、导语、正文、CTA、标签、图片、陈述与证据关联 | 保证可预览与可追溯 |
| 核验规则 | 精确数值、适用条件、禁止收益推断、冲突暂停 | 约束事实陈述与审核状态 |
| 合规规则 | 无依据价格、优惠、库存、体验、绝对化和竞品贬低禁用 | 避免营销误导 |

## 阶段分工

- `parse`：理解新任务和修改，继承当前会话，返回任务与修改范围。
- `plan`：只输出策略与取证计划，不写正文；查询必须说明业务目的。
- `supplement`：检查缺口、补查或放弃无证据卖点，避免无效循环。
- `write`：执行策略并引用事实；按平台编排图片与结构。
- `patch`：只返回指定段落补丁，代码拒绝越界修改。
- `review`：不信任作者自列 claims，从实际可发布文本提取并核查；输出 supported / unsupported / conflict / pending 及问题理由。
- `revise`：针对审核问题修订，保留已通过内容；不以免责声明掩盖虚假承诺。

八类场景使用轻量风险提醒，仍允许模型分析自定义或混合场景。内容创作不承诺软件兼容或性能实测；企业采购不编服务政策；新品需新旧款依据；节日不编优惠库存。

## 评审说明

审核是辅助检查，不能宣传为第三方认证或事实绝对证明。图片审核仅基于索引与文件，不宣称视觉模型已检查画面。最终验收必须分别记录真实 API、规则/模拟测试和未测项。
